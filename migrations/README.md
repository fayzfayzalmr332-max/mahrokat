# ترحيلات قاعدة البيانات

## ⚠️ الملف الفعّال الوحيد انتقل

المخطط الرئيسي الموحّد أصبح في المسار الذي يلتقطه **Supabase CLI** تلقائياً:

```
supabase/migrations/20260902000000_master_schema.sql
```

- **لا تضع أي ملف `.sql` جديد في هذا المجلد** إلا بصيغة `<timestamp>_<اسم>.sql` —
  أي ملف هنا سيُطبَّق على الإنتاج تلقائياً عند `supabase db push` (أو عبر
  GitHub Action عند الـ Push إلى `master`).
- ملف المطابقة الآلية: `supabase/verify_schema.sql` (خارج migrations عمداً — لا يُطبَّق أبداً).
- خطوات التفعيل اليدوي والآلي معاً: `docs/DEPLOYMENT.md`.

## مجلد `archive/`

الملفات التاريخية الأصلية (001_init → 006_fuel_liters) — محفوظة للمرجعية
والتتبع فقط، **لا يُنفَّذ منها شيء إطلاقاً**، وهي خارج `supabase/migrations/`
عمداً حتى لا يلتقطها الـ CLI.

| الحالة | ماذا تنفّذ؟ |
|---|---|
| قاعدة Supabase جديدة (صفحة بيضاء) | `db push` آلياً أو الملف الموحد يدوياً |
| قاعدة قائمة نفّذت 001–006 سابقاً | لا شيء إلزامياً — الملف الموحّد Idempotent |
